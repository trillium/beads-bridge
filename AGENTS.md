# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Add durable project-specific notes here as they are discovered through real work.
- Tests touching stores/config need `FUNNEL_BASE` set (e.g. `FUNNEL_BASE=https://example.test bun test ...`); without it those tests fail at import — see `src/config.ts`.
- Project foreground/backlog is label-based: `state:foreground` on a `projects` bead means foreground, everything else is backlog; promotion adds the label plus a when/why comment, demotion is never automatic — see `src/lib/relay.ts`. Lifecycle is separate: `state:deprecated` means closed/superseded (absence = active) and is set/cleared only through the `project_edit` MCP op.
- MCP tools live in `src/routes/mcp.ts` with logic in `src/lib/`; register new tools there and add the test file to the `test` script in `package.json`.
- A server cannot observe a client's loaded tools/list: staleness tools (`tool_surface_check`, `bridge_info`) compare caller-supplied snapshots or feedback-recorded triples vs live and return explicit unknown when there is no reference — never guess (see `docs/tool-surface-check.md`).
- All bead mutations (create/edit/comment/note/close/label) must go through `src/lib/mutate.ts`: shell-free argv, throw-on-failure, verify-after-write receipts. Never build shell strings for writes; `bd()` in `src/util.ts` is reads-only by convention.
- False-success guardrail (`src/lib/receipts.ts`): unverified mutations are errors naming operation/id/store (`requireVerified`/`unverifiedError`), never success — routes return MCP isError / GET 500, batches report partial failure.
- ChatGPT probes OAuth discovery at bare AND `/mcp`-suffixed well-known paths — every discovery doc must be mounted at both (see `src/routes/oauth.ts` Discovery + `src/routes/discovery.test.ts`).
- Live rounds-trip tests (`src/lib/relay-live.test.ts` is the template): a store's bead-id prefix comes from its bd config (`issue-prefix`/`BD_NAME`), never the store name (projects emits `project-*`, assertions emits `assert-*`) — receipt parsing derives candidates mechanically plus a CLI-authoritative fallback, see `src/lib/create.ts` (`expectedIdPrefixes`); shell `projects create` directly and parse the emitted `project-<id>`. Clean up with `projects delete <id> --force` + verify `show` returns null. Tests that spawn several store calls need a per-test `{ timeout }` — bun's 5s default is too tight.
- Live tests must NEVER touch production stores — use `src/lib/live-test-store.ts` (`initScratchStoreSync` + `redirectStoreEnv` for flexibly-pinned wrappers like `inbox`, `shimBdRouter` for hard-pinned ones like `projects`/`task`), run-derived `liveRunTag` (never a hardcoded task id), and a start-of-suite `sweepScratchBeadsSync` with a 30-min age guard on the legacy TAG. Setup goes in blocking sync statements at import (hook timeout options are not honored; top-level await is rejected by tsc under type:commonjs). Bun sharp edges this exists because of: spawnSync without explicit `env` reuses the process-start snapshot (Node passes live env — `runList` passes it explicitly); never pipe `bd init` through `head` (SIGPIPE half-initializes the store); never preset `BD_NAME` for `bd init` (breaks workspace resolution).
- Public-ingress auth lives in `src/lib/access-gate.ts`, not `src/server.ts`: Funnel forwards onto the loopback socket so `req.ip`/localhost can never separate public from local — the gate splits them by socket peer + Funnel forwarding headers (presence only withholds the localhost bypass, never grants) and requires an OAuth/toolKey bearer on every data/action route. Never re-add an address or User-Agent allow.
- `/mcp` has two gates, both in `src/routes/mcp.ts`: OAuth (exact `/mcp` audience) for remote callers, plus the never-expiring service key (`toolKey`) for the loopback MCPJungle gateway only (`isLoopbackServiceCall` — socket peer + no-forwarding-headers, same rule as the access gate). Never store an expiring OAuth access token as the gateway's static bearer again (2026-09-18 outage); re-register with `ops/jungle-register-bearer.sh`. A rejected loopback bearer logs a `jungle-bearer-mismatch` marker — grep that string first.
- Live MCP Activity UI (`GET /live`, docs/live-activity.md): `src/lib/activity.ts` ring + `withActivity` (wired inside the follow-on scope in `src/routes/mcp.ts`) + `liveRouter` in `src/routes/activity.ts`. Observational only; reads `currentScope()`/`HEARTBEAT_EXCLUDED_TOOLS`/telemetry parsers, changes no heartbeat/relay/follow-on semantics. Candidate visualization shapes sit beside it in `src/routes/live-variants.ts` + `src/lib/live-variants.ts` (`/live/variants`, `/live/v1`, `/live/jumbotron`, `/live/timeline`, `/live/log`, `/live/stats`) and share that same `/live/events` stream; canonical `/live` stays canonical and `renderLivePage` is the single source of its markup (it is what `/live/v1` serves too). Mobile-first: the navigation list is a drawer under 900px and the live content is the document body; one shared view per bridge instance (`src/lib/view-state.ts`) rides the same SSE fan-out as named `event: view` frames (revision last-write-wins) and is readable at `GET /live/view` — every `/live` route stays GET-only, so a viewer's own drawer tap is local by design (docs/live-activity.md "Drawer sync").
- Response footers compose in `src/lib/followons.ts` (`withResponseFooter`: relay-status body + follow-on lines + staleness triple, `heartbeat` registered as the default follow-on) with per-request tool/caller scope installed at the fetch boundary (`withFollowonScope`) — tool callbacks stay untouched. Heartbeat cursor/template rules live in `src/lib/heartbeat.ts` + `config/heartbeat.md`, documented in `docs/heartbeat.md`. `heartbeat`/`relay_status`/`timeout_probe` answer bare (loop prevention); footers are observational-only and bounded.
- Creation provenance (`src/lib/provenance.ts`): every create path stamps `source:<mcp|paste|batch|relay>` plus `by:<caller>` (OAuth clientId / caller key, sanitized, never a token) via `CreateInput.provenance` → `buildCreateArgs`. Caller-supplied `source:`/`by:` labels win; provenance leads and the total caps at 10 labels. Live round-trips live in `src/lib/provenance-live.test.ts`.
- Store guard (`src/lib/store-health.ts`, docs/store-health.md): every bead read/write probes `<store> where` and refuses a store whose CLI is broken or resolves to another store's workspace — never add a fallback store. Scratch-store test helpers set `BEADS_BRIDGE_STORE_GUARD=off`. On this host a global bd config makes `bd init` fail and ignores `BEADS_DIR`, so `*-live` tests cannot run here and a stray `bd create` lands in the real brain store — never probe with bare `bd`.
- Bead reads go through SQL first (`src/lib/sql.ts`, docs/sql-reads.md): one read-only SELECT door over the shared Dolt `brain_unified`, wrapped in `withSqlFallback` (logged bd fallback; `BEADS_BRIDGE_SQL=off` forces bd). A new read path must keep bd as the byte-identical source of truth and be proved with `ops/sql-parity/run.sh` (live, read-only, scratch dir on the brain host — never the live app dir). Never reintroduce `spawnSync`/`execSync` bead reads in request paths (they stall the bun event loop); `walkGraph` swallows `fetch` errors, so batch loading belongs in its `prefetch`. Tests that use scratch stores must run with `BEADS_BRIDGE_SQL=off` (the `live-test-store.ts` helpers do). bd resolves truncated ids by hash substring (`resolvePartialId`/`sqlResolvePartialIds`, mentions are often line-wrapped) and lists a bead's down edges in Dolt's plan order for `WHERE issue_id = ?` — not a sort, and `IN (...)`/UNION/wider projections reorder it, so `sqlDepEdges` stays one narrow `=` query per bead; prove changes with `ops/sql-parity` `ab.ts`/`deps.ts`/`partial.ts` (docs/sql-reads.md Deviations).
- `/live` main pane is the display-only event stream (docs/live-activity.md "Event stream"): the ring now records REDACTED, bounded arg values (`src/lib/redact.ts`); anything shown on `/live` must pass through it, and no new public paths may be added (vps01 allowlist is exact).
- Project writes resolve through `lookupProject` (`src/lib/relay.ts`): exact id first (read from the store, not a list window), then exact slug/title/alias; ambiguous or unmatched refs throw with candidates, never fuzzy-pick. Real P status is the `priority` field (`bd --priority`, verified by the `show` header) — a `priority:P0` label does nothing and is rejected; see docs/priority-and-project-resolution.md.
